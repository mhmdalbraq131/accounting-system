# المرحلة 1 — تدقيق الواجهة ووظائف الأزرار

## نطاق المرحلة
التأكد من أن عناصر التنقل والنماذج والإجراءات الظاهرة في الواجهة مرتبطة بوظائف حقيقية، وأنه لا توجد إجراءات UI ميتة أو غير موصولة.

## نتيجة التدقيق الحالي

### يعمل فعليًا
- التنقل بين وحدات النظام.
- فتح وإغلاق القائمة الجانبية على الشاشات الصغيرة.
- تسجيل الدخول عبر API.
- إنشاء البرامج.
- إنشاء الحجاج والمعتمرين.
- إنشاء الفروع.
- إنشاء المستخدمين وربطهم بفرع/دور.
- تعديل إعدادات النظام عبر الحفظ عند مغادرة الحقل.
- إنشاء العملاء والموردين وتعطيلهم بدل الحذف الفعلي.
- إنشاء الحسابات المحاسبية.
- إنشاء الصناديق والبنوك والمحافظ.
- إنشاء خدمات التأشيرات.
- إنشاء السندات وترحيلها وإلغاؤها وفق حالة السند.
- تحديث التقرير المالي وطباعة التقرير من المتصفح.
- إنشاء العملات.
- إنشاء المصروفات.
- أزرار الوصول السريع في لوحة التحكم.

### نواقص واجهة المرحلة 1 التي يجب إغلاقها قبل اعتمادها
1. لا يوجد زر واضح لتسجيل الخروج رغم وجود جلسة دخول محلية عبر `accounting_token`.
2. دالة جلب بيانات طباعة السند موجودة في API الواجهة، لكن لا يوجد زر «طباعة» فعلي داخل قائمة السندات يستخدمها.
3. النماذج العامة تعرض حالة الانشغال أثناء الحفظ، لكن أخطاء الإنشاء لا تعرض رسالة محلية واضحة داخل النموذج؛ يجب توحيد معالجة الخطأ في `FormPage` بدل ترك الاستثناء يصعد للواجهة.
4. توجد دوال قديمة تعتمد على `window.prompt` داخل `App` ولا تُستخدم حاليًا بعد التحول إلى النماذج المنظمة؛ يجب إزالتها لتقليل الكود الميت.
5. بعض صفحات البيانات تعرض البيانات فقط دون إجراء تعديل/تعطيل، مع أن الـAPI يدعم بعض عمليات التحديث/التعطيل؛ ستُراجع إجراءات كل كيان في المراحل الوظيفية اللاحقة ولا تُعتبر مكتملة لمجرد نجاح الإنشاء.

## معيار إغلاق المرحلة
لا تُعتبر المرحلة 1 مكتملة حتى:
- يتوفر تسجيل خروج واضح وآمن.
- تتوفر طباعة فعلية للسند من القائمة.
- تكون أخطاء النماذج مفهومة للمستخدم ولا تظهر كأخطاء React/JavaScript غير معالجة.
- يُزال الكود الميت المرتبط بالنماذج القديمة.
- يُجرى Build ناجح للواجهة بعد التعديلات.
