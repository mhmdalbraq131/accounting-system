# معمارية النظام

## الهدف
نظام محاسبي مستقل يعمل محليًا على الحاسب، مع قابلية الانتقال لاحقًا إلى شبكة محلية أو خادم دون تغيير جوهر النظام.

## الطبقات

```text
React + TypeScript (RTL)
        |
     REST API
        |
FastAPI / Python
        |
Accounting Domain Services
        |
PostgreSQL
```

## قواعد التصميم

1. المعاملات المالية تمر عبر طبقة النواة المحاسبية.
2. كل عملية مالية قابلة للترحيل تنتج قيدًا مزدوجًا متوازنًا.
3. حفظ المستند والقيد يتم داخل Transaction واحدة.
4. القيود المرحلة لا تعدل مباشرة؛ التصحيح يكون عبر عكس القيد أو مستند تصحيحي.
5. الصلاحيات منفصلة عن واجهة المستخدم.
6. كل عملية حساسة قابلة للتدقيق.
7. API هو حد التكامل المستقبلي مع MASARI أو أي نظام آخر.
